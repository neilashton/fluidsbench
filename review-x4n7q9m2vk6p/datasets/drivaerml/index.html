DrivAerML dataset

Dataset overview and leaderboard submission format for DrivAerML.

Dataset specification

DrivAerML is a high-fidelity CFD dataset for road-car external aerodynamics based on 500 parametrically morphed variants of the DrivAer notchback vehicle. It provides geometry, surface fields, volume fields, slices, and time-averaged forces and moments for machine-learning surrogate development.

The source dataset is maintained at caemldatasets.org/drivaerml. The dataset page describes the full Hugging Face layout, including STL geometry, VTP boundary fields, VTU volume fields, force/moment CSV files, and flow slices.

Dataset summary

Geometry
Parametrically morphed DrivAer notchback road-car variants.
Cases
500 CFD simulations.
Solver
OpenFOAM v2212 finite-volume simulations with custom workflow modifications.
Fidelity
Scale-resolving hybrid RANS-LES representative of industrial automotive aerodynamic workflows.
Mesh scale
Approximately 140 million volume grid cells and 8.8 million surface points per case.
License
CC BY-SA 4.0, as stated by the dataset source.

Open-reproducibility submission

Check this dataset's current submission status on the leaderboard before preparing a result. Contributions are accepted only while its exact scoring-support release is owner-approved, marked official, and open. For an open dataset, contributors propose one result directory at submissions/drivaerml/<submission-id>/ in the FluidsBench submission repository. The planned result package contains:

  • submission.json for model metadata and the required scalar metrics;
  • evaluation-evidence.json linking those submitter-provided metrics to the declared evaluation revision and profile-index checksum;
  • discretization.json describing the training input and supervision supports, inference input, direct model outputs, and mapping to the official scoring support;
  • discretization/cases.jsonl recording case-level counts, domains, mapping, and declared scoring coverage;
  • metrics/cases.json recording the official-support errors, unweighted and area-, length-, or volume-weighted sufficient statistics, and exact coverage for every declared evaluation case;
  • profiles/index.json listing the lightweight profile chunks; and
  • profiles/chunk-*.json containing profile coordinates and predictions for the declared test cases.

FluidsBench uses an open reproducibility track. The declared evaluation partition, scored case lists, and ground truth are public. Evaluation cases must not be used for fitting, hyperparameter selection, or preprocessing statistics. Contributors will calculate the metrics and extract the profiles from their own predictions. Each dataset specification fixes the locations, IDs, weights, targets, and coverage used for final scoring. A model may infer on a different point set, mesh, or grid, but its final predictions must be mapped onto every required entity in the release-bound public field files before the reference evaluator calculates the errors. Large cases may be processed in chunks, but contributors must sum the sufficient statistics across all chunks before calculating a case metric; chunk-level L2 values are never averaged. Leaderboard field errors are calculated on the declared evaluation/test cases, not on the training cases. Full meshes and volume fields are not committed to the submission repository. Contributors may optionally publish example cases or the complete scored predictions in a public, immutable external repository and link that artifact from the submission. Use the DrivAerML benchmark specification for the exact split, metric, case, panel, station, and quantity IDs. The reference equations and code define how the scalar values must be calculated, and the worked examples show the JSON structure.

Before opening a pull request, run python scripts/validate_submission.py --contributor-stage submissions/drivaerml/<submission-id>. The validator checks the schema, split identity, scoring-support binding, derived-score arithmetic, profile coverage, reported discretization, array lengths, ordering, finite values, and file hashes. It checks the submitted package's internal consistency; it does not run the contributor's model or recalculate base metrics from full fields.

A passing validator or pull request will not make a result official. Official results require maintainer approval of the validated submission package. Public code, model, and environment artifacts and their documentation are optional. If supplied, they must use stable links and include the revisions, digests, and licences required by the submission schema; the leaderboard reports those details. Their absence does not change accuracy rank, citation eligibility, or promotion eligibility. Prediction sharing is also optional. When prediction artifacts are shared, the leaderboard separately reports their coverage, artifact-check status, and whether any metrics were recomputed; it does not collapse those distinct checks into a generic “verified” badge. The public validation record states exactly what FluidsBench checked.

Prototype notice: any case IDs, ground truth, profile values, or leaderboard rows labelled prototype are illustrative dummy data. Dataset owners must replace and approve those materials before their dataset opens; a prototype row is never an official or approved result.

Scoring support and complete coverage

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

Scored support Public field file and association Required coverage Relative-L2 pair
Three-dimensional vehicle boundary run_<case-id>/boundary_<case-id>.vtp; pMeanTrim and wallShearStressMeanTrim in VTK CellData (CpMeanTrim is also available for coefficient diagnostics) Every polygon carrying the scored pressure and wall-shear fields Area-weighted primary; unweighted polygon (each polygon counts equally) secondary

How to calculate large cases

  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for both the unweighted and area-, length-, or volume-weighted variants, together with entity count and total area, length, or volume. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package itself stays small and records exact coverage plus the per-case sufficient statistics used to reproduce both relative-L2 values.

Metric definitions

Relative L2 error
For each evaluation/test geometry, map predictions to every entity in the release-bound public field support and return predictions and targets to dimensional physical space, \(q^\ast = T_q^{-1}(q)\). Calculate both paired relative-L2 values from the accumulated sufficient statistics: area-weighted L2 is primary on the boundary, while unweighted cell L2 (each cell counts equally) is primary in the flow volume. Report the complete-case percentages first, then take the arithmetic mean of the geometry-level values.
Relative L1 error
When reported as a supplementary metric, relative L1 uses the same complete dimensional support and the primary weighting for that domain. Calculate a percentage for each geometry, then take the arithmetic mean of the geometry-level percentages.
Dimensional evaluation
Relative L1 and L2 metrics are not computed on normalized, standardized, or non-dimensional training targets. If a model predicts normalized values, the submission/evaluator must undo that transform before scoring. Cd, Cl, and Cp-cut comparisons remain coefficient-based by definition.
Surface pressure relative L1/L2
Relative L1 and L2 error for dimensional surface pressure p_surface_pred against the evaluator surface pressure values. Cp is used only for the Cp-cut comparisons and plots.
Surface wall-shear relative L1/L2
Relative L1 and L2 error for the wall-shear vector \(\tau_w = (\tau_{w,x}, \tau_{w,y}, \tau_{w,z})\) on the vehicle surface.
Volume velocity relative L1/L2
Relative L1 and L2 error for the velocity vector \(u = (u_x, u_y, u_z)\) on every field-bearing entity in the release-bound reconstructed volume support.
Volume pressure relative L1/L2
Relative L1 and L2 error for pressure on every field-bearing entity in that same public volume support.
AB-UPT convention
The secondary unweighted polygon relative L2 (each polygon counts equally) is the AB-UPT-compatible value: targets may be normalized for training, but evaluation uses unnormalized predictions and targets. FluidsBench additionally uses the area-weighted boundary value as its primary surface metric.
Coefficient of determination
For scalar values \(y_i\), \(R^2 = 1 - \sum_i(\hat{y}_i - y_i)^2 / \sum_i(y_i - \bar{y})^2\). Higher is better; 1.0 is perfect.
Cd and Cl R2
R2 computed over all evaluated cases using predicted drag coefficient cd_pred and lift coefficient cl_pred. AB-UPT computes these forces from high-resolution surface pressure and wall shear stress predictions.
Force R2
Mean of Cd R2 and Cl R2.
Cp cut R2
One global R2 over all selected surface pressure coefficient samples from the held-out test cases. The evaluator flattens cp_pred and ground-truth cp across case_id, cut_id, station_id, and cut sample locations before computing R2. The plotted trace is chosen with the leaderboard station selector.
Cp cut comparisons
Per-case and per-cut R2 values can be reported as profile comparisons, but the leaderboard ranking should use the global held-out score so that cases with low Cp variance do not dominate through unstable per-case averages.
Velocity profile R2
R2 over selected wake profile samples behind the vehicle. Unless the benchmark package states otherwise, the score is computed on the velocity vector components flattened across stations, cases, and sample points.
